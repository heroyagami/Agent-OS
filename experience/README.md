# 经验学习中心

本目录定义如何把已验收实践转化为候选规则。它不是原始聊天、客户文件或案件材料的归档区。

## 入口

- [经验提炼 Skill](../skills/experience-curator/SKILL.md)：识别可复用方法、脱敏、确定适用范围。
- [晋升工作流](../workflows/experience-promotion.md)：候选、审查、测试、批准、合入和回滚。
- [经验提案模板](../templates/experience-proposal.md)：人工提案记录。
- [提案 Schema](../registry/schema/experience-proposal.schema.json)：机器可校验字段。
- [校验脚本](../scripts/check_experience_proposals.py)：检查结构、生命周期闸门和敏感字段名。

## 存储边界

- 公开仓库只允许存放脱敏的通用规则、必要来源引用和测试摘要。
- 原始对话、客户名称、案号、合同/证据原文、个人信息、音频、密钥和访问令牌留在受控私有系统。
- 若需要保留候选提案 JSON，放在受访问控制的私有存储或私有分支；公开仓库默认不提交真实任务提案。
- source_task_refs 只能是受控引用标识，不得使用能公开访问客户文件的链接。

## 晋升原则

1. 先判断经验是否可复现、是否能减少错误或返工。
2. 优先 Project 级规则，其次现有 Skill/reference。
3. Core 必须有跨项目证据、反例审查和维护者批准。
4. 正例与反例均通过后，才能进入 tested；隐私审查通过后才能批准。
5. 维护者批准后才可合入；记录提交、回归结果和回滚方法。

校验脚本只做结构和部分隐私字段检查，不代替人工隐私审查、专业审查或宿主访问控制。
