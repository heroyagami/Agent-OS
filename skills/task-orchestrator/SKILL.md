# Task Orchestrator

## 最小工作流

1. **定义**：确认交付物、完成边界、验收证据、资源预算、授权范围；先读取项目已有计划与规范。缺失信息能低风险假设则记录后继续，影响方向/授权则请求最少必要信息。
2. **拆解**：从最终验收倒推产物，列输入、输出、依赖与负责人。先读 [任务拆解](references/task-decomposition.md)，把关键路径和最大失败风险放到计划前面。
3. **探针**：给关键假设设计最便宜的可证伪实验；失败就调整计划，成功再扩展到 MVP 和完整交付。
4. **执行**：逐个完成已满足依赖的任务。并行前判断输入、写入冲突、工具约束与协调收益；没有委派能力或授权则顺序完成，不能虚构子 Agent。
5. **闸门**：到方向、核心样本、整合和交付节点读取 [质量闸门](references/quality-gates.md)，用实际证据决定通过、阻塞或允许的有条件通过。
6. **反证**：重要阶段读取 [对抗式审查](references/adversarial-review.md)，以缺陷和反例检验结果。记录审查独立性，修复后仅复验相关及受影响部分。
7. **交付**：提供能使用的产物与位置、通过/未通过/未验证的检查、遗留缺陷及限制；外部写入后回读最终对象。
8. **沉淀**：记录失败原因、有效修复与反例；共享规则变更须有验证、维护者审查及回滚方案，不能自主污染全局规则。

## 记录与范围

记录可以在会话或项目原有文档中维护，不强制创建一套新文件。需要标准格式时，从完整 Agent OS 源目录的 `templates/` 读取任务简报、执行计划、审查报告；独立安装本 Skill 时可直接使用本文件与 references 中的字段，不依赖外部模板。

计划随证据更新，不是一次定死的清单。预算不足或关键闸门阻塞时报告具体缺口，不能改写验收标准来宣称完成。

## 示例

任务：做一条带旁白和字幕的 60 秒产品视频。

- 倒推交付：可播放成片 → 声画整合 → 已验证样片 → 分镜/配音/素材契约。
- 关键假设：中文字体可用、人物一致、配音时长与字幕同步；先制作 8 秒样片验证。
- 并行判断：分镜冻结后可分别制作画面与声音；两者共写时间轴则应由一个负责人整合。
- 停止条件：完整成片满足规格，P0/P1 清零，P2 已处理，实际播放与导出检查通过。
