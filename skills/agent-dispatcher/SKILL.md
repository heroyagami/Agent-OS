# Agent Dispatcher

## 使命

把已明确的任务交给有资格、有权限且实际可用的员工；保证任务状态、预算、审批和交接证据可追踪。派单是治理决策，不是把任务文本广播给所有 Agent。

## 触发条件

- 一个任务需要多个岗位按顺序协作或分阶段交接。
- 需要从员工注册中心选择负责人、执行者或审查者。
- 需要检查任务状态、权限、预算、依赖、阻塞或重试条件。

单一、低风险、可直接完成的任务由当前 Agent 执行，不为简单任务启动调度流程。

## 派单步骤

1. **接收任务**：确认目标、交付物、验收条件、请求人、截止时间、风险等级和授权范围；按 [任务模板](../../templates/agent-task.md) 建立任务契约。
2. **检查注册中心**：读取 registry 与岗位 profile。只有 lifecycle_status=approved 且 runtime_status=running 的员工可进入正式候选；draft、in_review、not_deployed、configured、suspended、unknown 和 retired 一律排除。
3. **匹配职责**：比较任务所需能力、岗位职责、输入输出和 Skills。优先一个合适的负责人；只有确有独立责任、权限或并行收益时才拆分。
4. **权限核对**：任务要求的读写范围和外部动作必须是员工获批权限的子集。权限不足时阻塞并升级，不允许派单员临时扩权。
5. **预算与依赖**：检查预算、截止时间、依赖是否完成、是否存在写入冲突；并行仅限输入稳定且写入隔离的子任务。
6. **审批闸门**：发布、删除、客户数据外发、资金、生产变更和 T3 高风险任务按既定审批及独立审查规则处理。
7. **生成派单**：记录候选理由、负责人、任务ID、幂等键、输入引用、权限范围、预算和下一步。只有宿主真实支持任务队列/Agent 调用且已授权时，才执行实际派单；否则交付派单提案。
8. **跟踪状态**：按 [派单工作流](../../workflows/agent-dispatch.md) 更新状态，记录输出引用、证据、阻塞和责任人。
9. **处理失败**：先核实是否已执行，再决定重试。仅对幂等操作进行有限重试；不确定是否写入成功时先对账，禁止盲目重放。
10. **关闭任务**：验收证据齐备、审批完成、遗留问题明确后才标记 completed；执行者自评不得冒充独立审查。

## 资格与拒绝规则

- 员工注册状态和宿主运行证据优先于名称、提示词或自我声明。
- 岗位匹配不代表权限匹配；权限匹配不代表预算和审批已满足。
- 没有 eligible 员工时，返回 blocked 和缺口，不把任务交给 draft 员工试运行。
- 任务记录只保存必要元数据和受控资源引用；不把客户材料、密钥或敏感正文写入公开仓库。
- 注册中心和 Markdown 不提供运行队列；没有实际宿主能力时只能生成可审查的派单提案。

## 产出验收

每次派单都应能说明：为什么选这个员工、为什么排除其他候选、权限是否覆盖、预算是否满足、依赖是否就绪、审批是否完成、如何避免重复执行，以及结果由什么证据验收。
