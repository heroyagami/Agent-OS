# AI员工团队设计工作流

> 从业务需求形成可审查的团队方案与注册草案；不自动创建运行时、账号、凭据或权限。

## 触发与输入

用户要求建立/调整 AI 员工团队、长期岗位，或将重复工作改造成可持续 Agent 流程时触发。输入包括业务目标、现有流程、频率、输入输出、时限、数据等级、预算、质量标准、审批点和可用宿主。关键资料缺失时先盘点现有仓库；只有影响架构或授权的缺口才询问。

## 阶段与状态

| 阶段 | 主要动作 | 输出 | 通过条件 |
| --- | --- | --- | --- |
| Intake | 定义目标、范围、约束和验收 | 任务简报 | 目标可观察，授权清楚 |
| Inventory | 读取注册中心、Skills、Workflows、Tools | 现有能力清单 | 已检查重复能力 |
| Classify | 比较 Agent、Skill、Workflow、Tool 或直接执行 | 架构决策记录 | 新 Agent 有独立责任依据 |
| Design | 设计最小团队、岗位契约和交接 | 团队提案、岗位卡 | 每个角色有输入输出、边界和验收 |
| Risk review | 审查权限、数据、成本、失败分支和回滚 | 风险/权限矩阵 | 高影响操作有审批与恢复方案 |
| Approval | 用户/维护者审阅 | 审批记录 | 未批准事项保持 draft |
| Register | 校验并登记获批配置 | registry 更新 | Schema、引用、唯一 ID、状态检查通过 |
| Deploy | 在指定宿主配置 Agent 与权限 | 部署记录、运行证据 | 宿主实际测试通过，否则标记未部署 |

## 决策规则

1. 先复用现有员工和 Skills；不要因一个岗位会多项技能就拆成多个 Agent。
2. 只有责任、上下文、权限边界或生命周期确实独立时，才新增 Agent。
3. 比较协调成本、模型成本、返工和质量收益，不以团队人数为绩效。
4. 未设置负责人、审批、预算、数据边界或停止条件时，不进入批准/部署阶段。
5. 交接只传递任务上下文与产物引用，不传递密钥、账号或更高权限。
6. 批准团队方案不等于批准每项外部动作；发布、删除、付款和生产变更仍需对应授权。

## 标准交付包

1. 业务目标与架构决策记录。
2. 最小团队拓扑和岗位职责表。
3. 每个岗位的 JSON profile 草案。
4. 工具白名单、数据边界、审批和预算矩阵。
5. 结构化交接、失败分支和回滚方案。
6. 正例、反例、权限拒绝和成本停止验收用例。
7. 当前状态与对应证据：draft / in_review / approved / configured / running。

## 停止与升级

缺少授权、敏感资料外发风险、无回滚方案、预算不明或宿主能力无法验证时，停止受影响阶段，保留可完成的设计工作并明确阻塞项。
