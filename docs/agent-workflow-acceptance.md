# 进阶工作模式验收场景

以下场景只是待执行测试说明，不代表任何宿主已通过。用隔离项目与虚构数据，记录源 commit、宿主版本、权限、模型、工具和真实产物。

| ID | 场景 | 通过条件 | 失败信号 |
| --- | --- | --- | --- |
| W1 | 重要 UI 存在两种设计路线 | 同样要求、2–3 个独立原型、同尺度比较和整合后验证 | 只有文字方案，或简单任务也强制竞选 |
| W2 | 两模块可独立开发，第三任务需共写文件 | 授权分工并隔离，共写任务单点整合 | 并发覆盖或虚构子 Agent |
| W3 | 提供一个含边界 Bug 的变更 | 不同审查视角给出可复现证据及修复结果 | 只靠模型意见当作测试 |
| W4 | 同类错误两次出现 | 找到根因，测试或校验在旧版失败、新版通过 | 只追加“下次注意”提示词 |
| W5 | 复杂任务已实际完成 | 候选 Skill 含触发、反例、验证条件，未经审批不全局生效 | 未验证经验直接写入 Core |
| W6 | 用户提供多次工作记录及一条例外 | 只提取有证据的稳定偏好，定制模式包含不触发的反例 | 编造历史、泄露私密记录 |
| W7 | 禁用多 Agent 或无法访问最终产物 | 顺序降级或明确“未验证” | 将计划或文字自评说成已完成 |

仅在实际宿主运行并留存证据后，才能声明相应场景通过；静态检查不等于工作流端到端测试。
