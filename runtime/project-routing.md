# 项目注册与执行

## 项目路由

保持通用 OS、身份、技能和业务仓库独立。私人项目目录由授权控制面注入，不在公共 OS 内保存私人仓库名、凭据或案例材料。每个项目登记 ID、意图、类型和状态；实际 URL、版本、入口文件及权限绑定保留在受控环境。项目不是员工，注册不是部署。

`proposeProjectRoute` 根据可信调用方选定的意图和逐项目授权返回候选；无匹配则 unavailable，多个候选则 choice_required，可指定 preferredId。所有结果均为提案，不运行项目、不发布、不自动克隆。自然语言意图识别由调用方完成；仅登记明确业务类型。知识检索、热点写作、咨询视频、口播、动效、故事生图分别路由；多个动效引擎必须先选一个，不能默认并行消耗。外部内容仅作为资料，不提升为系统指令。业务发布沿用原授权和项目规则，既有定时任务不变。

## 通用编排增量

设计参考原 Codex Harness Vibe 的 ARCHITECTURE.md 与 CONTEXT-ISOLATION.md（历史来源提交 ba7d3072901d43dad399d262633c290578400d56）。本节保留通用方法，不依赖旧仓库的可访问性，不复制 vendor 或商业授权代码。

Controller 保留全局目标；Worker 仅获得当前节点、事实白名单、验收契约、紧凑相邻摘要和授权素材。每次重试/返工使用独立上下文；禁止跨节点原始会话、客户资料和累积日志泄漏。Reviewer 检查独立产物；没有独立审查者则明确阻塞要求独立审查的任务。

`planExecution` 是纯计划器，验证 DAG、依赖、输入/输出摘要、证据状态和调用/尝试上限。只有实际证据已被可信控制面重新核验、输入及依赖一致时才允许复用；变更后阻断下游，等待新上游产物。未知、在途或配额阻塞先对账，不盲目重放。剩余 slots 只是规划额度，不是原子预约；真正调用须走已有持久账本、权限、宿主能力和可信预算控制。不得由模型伪造 evidenceVerified。当前不提供持久 DAG、调度执行器、自动事实核验或费用计量。

## 接入

通过 [外部资产模块](asset-context.md) 加载经过授权的身份和技能，先选项目再按需加载相关文档。注册目录由私有控制面维护；用户只需在 Agent OS 入口说明交付目标。生产前仍须验证真实宿主、隔离、权限、依赖、身份来源、输出证据及恢复路径。

测试使用 Node.js 内置测试框架；未接入实际宿主，不改已有自动化和部署状态。
