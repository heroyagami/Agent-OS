# 任务拆解、逆向规划与风险前置

读取时机：T2/T3 建立或重做计划时。目标是减少返工，不是拆出最多任务。

## 从结果倒推

1. 将目标写成可观察的成果：谁在什么场景使用，最终文件/行为是什么。
2. 将每项要求对应到验收证据；无法验证的“高级”“完善”需变成场景或指标。
3. 从最终产物反向列出中间产物，再转成执行顺序。拆到能独立检查且有清晰边界即可。
4. 从基本事实与硬约束推导最小方案：哪些步骤必须做，哪些只是惯例，能否先用现有资产验证。

每个任务至少记录：

| 字段 | 内容 |
| --- | --- |
| ID / 负责人 | 唯一编号与交付责任；单 Agent 可全部自领 |
| 输入 / 前置条件 | 已确认资料、版本、权限、前置任务 |
| 动作 / 输出 | 具体操作与可定位的产物 |
| 依赖 | 前置 ID；无依赖写“无” |
| 验收 / 证据 | 如何判断合格，证据保存位置 |
| 风险 / 回退 | 失败影响、触发条件、恢复方式 |

## 依赖图与并行判断

依赖应是有向无环图（DAG）。若 A 等 B、B 又等 A，先做小探针或明确接口以打破循环。

```text
A 简报与规格 → B 8 秒样片 → C 分镜/时间轴契约
C → D 画面素材 ─┐
C → E 配音字幕 ─┴→ F 整合 → G 成片验收
```

标出最长依赖链及耗时估计；关键路径上的失败优先处理。外部审批、昂贵生成和稀缺工具也是依赖。

并行须全部成立：前置输入稳定；交付接口明确；写入文件/远端对象不冲突；执行权限允许；资源可用；节省时间大于协调与合并成本。不满足就顺序执行或隔离工作副本。

如使用获授权的子 Agent，给出范围、输入版本、负责文件、禁止触碰区域、输出契约与验收；告知其存在其他协作者，不得撤销他人修改。主执行者负责整合并核验实际成果。

## 风险与关键假设

先做失败预演：假设最终交付失败，列出最可能的 3–5 个原因，并说明最早可观察信号、影响、缓解和责任人。

以“影响 × 不确定性”粗排风险，并结合验证成本安排探针；不伪造精确概率。关键假设必须有否定条件，不能只寻找支持证据。

| 假设 | 最小实验 | 通过/否定条件 | 否定后的动作 |
| --- | --- | --- | --- |
| 导出环境有指定中文字体 | 渲染一行目标文案 | 无缺字且字形符合规格 / 缺字或替换 | 安装获授权字体或更换方案，再测 |
| 外部 API 满足吞吐 | 非生产小样调用 | 在约定预算/限额内完成 / 超限 | 降批量或改技术路线 |

## MVP 与重规划

MVP 必须验证最危险的端到端路径；只做漂亮外壳不足以验证核心假设。方向通过后补齐所有约定产物。

关键假设失败、依赖变化、范围变化或同一故障连续出现时重规划。更新影响的任务与验收，不重写已经有效的全部方案。只剩低收益细节时按缺陷等级决定停止，不为了流程而新增阶段。
