# Experience Curator

## 使命

把真正可复用的经验变成可验证、可回滚的候选规则，而不是把聊天记录或一次成功结果复制进知识库。保护项目、客户和个人信息，优先在最局部范围修复问题。

## 触发条件

- 重要任务完成并通过验收，需要复盘可复用方法。
- 同类错误重复发生，已找到可验证的根因或稳定修复。
- 用户明确要求沉淀 Skill、更新项目规范或提出通用规则。

单次偶发、没有证据、没有复现条件或只有模型主观评价时，不提出通用 Skill。

## 提炼流程

1. **确认来源**：只使用已完成且有验收证据的任务、测试记录或用户明确提供的实践。记录私有来源引用，不复制原始聊天。
2. **识别模式**：提炼触发条件、问题、根因、适用边界、步骤、决策标准、输出契约和失败信号；区分事实、假设与推断。
3. **判断价值**：确认方法可重复、能减少错误/返工或提升质量；若只是一次性事实、个人偏好或临时 workaround，不升格为 Skill。
4. **隐私脱敏**：删除客户名称、案号、联系方式、合同原文、敏感个人信息、密钥、访问令牌和无关私人细节。公开提案只保留脱敏摘要及受控来源引用。
5. **选择范围**：优先项目规则，其次现有 Skill/reference；只有跨项目证据充分、稳定通用时才建议 Core。不得为了方便把局部经验升级为全局规则。
6. **生成提案**：按 [经验提案模板](../../templates/experience-proposal.md) 和 [Proposal Schema](../../registry/schema/experience-proposal.schema.json) 建立候选记录。
7. **正反例测试**：至少一个正例和一个反例；写明输入摘要、预期行为、实际结果和证据。反例测试通过意味着系统正确拒绝或限制不适用情形。
8. **隐私与对抗审查**：检查是否泄露信息、过度泛化、与现有规则冲突、扩大权限或引入新的失败路径。
9. **维护者审批**：只有经授权维护者批准后才可合入；Core 还需跨项目证据。拒绝或未完成测试的提案保持候选/阻塞状态。
10. **合入与回滚**：局部修改、版本化提交、运行回归检查；记录合入目标、提交和回滚方式。验证失败则撤回，不保留错误规则。

## 晋升等级

| 范围 | 适用条件 | 审批门槛 |
| --- | --- | --- |
| Project | 仅在一个项目/业务流程中稳定有效 | 项目负责人审查与项目回归 |
| Skill / reference | 可跨多个任务复用的专业方法 | Skill 维护者审查，正反例测试 |
| Core | 跨项目、跨领域仍成立的通用原则 | 更强证据、独立反证和仓库维护者批准 |

## 禁止事项

- 不把整段对话、客户原文、案件材料或秘密提交到公开仓库。
- 不因一次成功就宣称方法普遍有效。
- 不自动修改共享 Skill、Core、适配器或用户全局指令。
- 不把模型审阅称为独立人工审批。
- 不删除失败记录来美化结果；记录失败原因和回滚。

## 交付验收

提案应包含可追踪来源、脱敏说明、适用条件、明确反例、正反例结果、证据引用、目标范围、维护者审批和回滚方案。没有这些内容时只输出复盘摘要，不晋升共享知识。
