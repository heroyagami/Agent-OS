# 成套文档交付偏好

## 触发与目标

用户要求制作可打印、可递交、可邮寄的投标文件、询价响应、报价标及配套公司资料时，主动完成整套交付，不等用户再次提醒封面、原始报价表、排版或盖章位置。单纯咨询、只改一个字段、只提取资料时，按原范围处理，不扩大为整套标书。

## 默认执行

1. 先读本次采购文件、原始表格和用户已提供的公司资料目录，再确定成果组成、递交方式及真正缺少的信息。已有资料先找、先核对，不把旧项目待补清单直接当成本项目要求。
2. 交付包含采购方指定原表，填妥已知报价、单位、联系人、电话、日期和数量。保留原始技术参数、合并单元格及有效打印设置，不能只在自拟正文中写一个总价来代替原表。
3. 成套文件适合使用封面且无相反要求时，主动加简洁封面，写项目名称、编号、报价单位、联络方式及已确定日期，按需要留盖章位置。不得把封面说成采购方明确要求，除非文件确有规定。
4. 核对是否分商务标、技术标、报价标或单独密封。明确要求分开的必须分开；未要求分开且用户要整套打印时，按封面、原始报价表、方案、资格附件、相关案例的清晰顺序整合。不得自行虚构份数、正副本或封装要求。
5. 报价变更时，同步核对原报价表、正文、大小写金额、附件、文件名和元数据。日期使用当前任务明确约定的口径，区分报价日、截止日、开标日及寄出日；不把某次指定的开标日期当成以后默认。
6. 区分电子盖章版和手动签章打印版。纸质手盖版保留盖章及本人签字位置，去掉本次新贴的电子章；证明附件原有印章不抹除。仅在已获授权时使用用户提供的真实章或签名，不仿造，也不把图像章称为可验真的数字签名。
7. 选择与本项目相近的案例图片，按真实内容标注。用户提供素材要求入库时，复制原图、按案例或类型分组并保留来源信息；不能把实景当效果图、把照片当合同，也不能补造项目金额或交付日期。
8. 文件完成后逐页打开实际导出检查。主标题、表头、短字段、金额、图片与页码按用途居中，叙述及技术说明保持适合连续阅读的对齐；检查断页、裁切、印章位置及横竖向打印。只检查文本不能声称已看过排版。
9. 保存到用户指定的项目目录，按当前阶段只交最少必需文件。用户正在补资料或要求逐个发送源文件时，只交约定的可编辑文件，不提前附 PDF、旧 DOC 或压缩包；定稿后再按采购要求生成打印及提交文件。需要整套打印且允许合并时，给出一个清楚命名的完整 PDF；必须分册时分别交付。只保留一套明确的最新交付，不默认堆叠历史版本；用户要求整理时，把重复生成稿及不需发送的辅助文件移入“可删除”，原件和唯一有效证据另行保护。
10. 最后只说明应打印哪个文件、需要手动处理的签章位置，以及本次实际要求的递交和送达时间。内部待办、工具路径和不相关的历史项目承诺不进入对外文件；未完成的关键项如实说明。

## 投标编制与交接补充

以下记录2026年11月11日用户明确纠正并要求写入 Agent OS 的工作偏好，不把某一标的分册、份数、税率或证明要求推广到所有项目。

### 原格式与证明材料

1. 尽量保留甲方附件原有标题居中、字号、表格列序、合并单元格、表尾说明和页面方向。封套不加无必要的辅助页眉或内部编制标题；不因统一设计而大改甲方格式。
2. 先读清采购公告、报名材料、正式采购文件、补充资料及澄清，再核对资格和符合性要求。区分评委填写的审查表与供应商填写的索引表，不擅自代评委打勾或签字；应填表格、附件、目录与页码主动核对。
3. 报名材料中的营业执照、声明等与报价书已有内容去重；有用的查询结果可作为对应资格佐证补入并更新索引。核实查询对象、名单类型、日期及结果：平台首页、登录工作台、普通企业搜索页不能冒充暂停、失信或严重违法名单的查询证明；旧截图不得改成新查询日期。
4. 证明图片可裁白边、按比例放大，四周留少量边距，不贴着文字或印章裁。优先用文档显示裁剪，保留原图；身份证默认完整保留，不裁掉边角或信息。不得编辑证明中的文字、日期或签章来替代正式更正。
5. 黄色仅用于真实待补或待核定项目。已确认报价、已授权完成的成本拆分和已补齐资料及时去黄，并同步当前可编辑稿与后续导出；真正缺证明的项目保留明确提示，不能只删除黄色就当完成。成本拆分按授权自主合理测算、核对合计及依据，测算税率不等于认定企业税务资格。
6. 业绩证明按用户指定项目和页数预留独立位置，例如本次为三项各三页。证明到位后替换占位内容，补真实金额、合同日期和联系人；超过预留页数就更新全部目录索引，不裁掉关键证明或把历史日期改成开标日。已解释的同一问题记录状态，不在每条回复反复提醒；新证据或实质性阻断仍需准确说明，不把用户口头确认写成出具方正式更正。

### 编辑稿与正式提交稿

1. 默认交接最少文件；用户明确只发三个文件时，交付目录就保留对应三份，不额外混入说明文件、预览 PDF、多种 Word 格式或 ZIP。微信说明另给可直接复制的短文。这里的“三个”是当次约定，其他项目按实际文件组成。
2. 给交接人和打印店编辑的格式，与交给采购方的格式分开核对。DOCX 可按用户约定用于补业绩；采购文件明确要求 DOC 时，最终须真实另存为 Word 97—2003 的 `.doc` 并重新打开检查，不能只改后缀，也不能以 `.docx` 替代规定的 `.doc` 后宣称一定符合。采购方要求保密或其他专用格式时依其规定。
3. 文件名便于外发识别，保留清楚的编号、用途及公司全称后缀；有甲方固定命名时严格遵照。两册要求同基名时用不同子文件夹区分，避免覆盖。不能把内部交接编号或“待补”混入正式提交文件名。
4. 纸质手盖流程按本项目要求办理：定稿、打印正本、本人亲签和实体盖章、制作副本及签章扫描件，再生成与正本内容一致的正式电子文件及可点击目录。若要求两册各 DOC、PDF，最终每个介质是四个正式文件；按实际要求准备光盘和 U 盘，换电脑逐个试开。当前编辑稿不直接刻盘，转换后复核分页、目录、图片和签章。

### 简短且明确的交接

1. 分别提供“给交接人”和“给打印店”两段短说明，用短句和具体动作；不擅自发送微信。交接人不爱看文字时提供可直接读成语音的版本，打印细节交给打印店，不把整份内部核对记录塞给交接人。
2. 不只说“带三袋资料”。按本次文件逐袋写明文件名称、正副本数量及介质内容，并写密封、封口盖章和封套要求。例如甲方要求价格文件与报价书分别装袋时，写清“价格文件：正本一、副本二”“报价书：正本一、副本二”“光盘一、U盘一”；这不是所有项目的固定份数。
3. 正式册名沿用甲方规定。甲方区分“价格文件”和“报价书”时，不擅自合成一本“投标书”；可向交接人解释为“价格册”和“资质技术册”，防止放错金额或封错袋。逐册核对报价信息是否允许出现。
4. 区分文字阅读偏好与行业能力。交接人已被用户确认熟悉项目技术时，删除“找懂技术的人同行”等无依据的默认安排，不因其需要简短说明就推断其不懂专业。人员配置另按采购文件和明确澄清核实；个别人的姓名、联系方式与能力记录留在私有项目上下文。

## 边界与反例

- 当次采购文件、固定格式及用户明确要求优先。单页报价表、只改金额、明确不加封面或必须分封的任务，不机械套用上述完整装订顺序。
- 某次用户决定不提交一类证明材料，不等于以后所有项目都可省略。记录当次决定及采购方澄清，不改写原始要求，不虚称已提供。
- 新价格、未知联系人、资格声明、合同业绩及证件状态要有依据；低风险可逆排版可自主处理，关键事实不得猜填。
- 印刷章、签字、封口要求和递交份数按本次文件办理；不得承诺仅凭排版齐全就一定通过资格或符合性审查。
- 本仓库只保存工作偏好和通用方法。公司证件、身份证、章与签名图片、真实报价、私人联系方式及案例原图留在用户授权的资料库，不随偏好发布。
